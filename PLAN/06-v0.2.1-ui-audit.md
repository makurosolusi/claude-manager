## P0: wrong information or broken layout

### P0-1 · Role "Kind" is misclassified (user finding 5)
- **Where:** `src/web/lib/roles.aggregate.ts:26-30`, `src/web/pages/roles.page.tsx:33-34`, `src/web/components/role.tables.tsx:103`, `src/web/lib/color.tokens.ts:69,88-94`
- **Problem:** any name missing from `meta.roles` counts as `custom`. So `general-purpose`, `Explore`, `Plan`, `fork`, `claude`, `web-fetch`, `statusline-setup` and `ui-ux` all show "custom", although `/api/meta` lists only the 6 presets.
- **Why:** "custom" should mean "made with `claude-manager roles add`". Here it labels agents that came from somewhere else.
- **Fix:** derive the kind **only** from the `meta.roles[].source` roster and never from the name: `preset` → preset, `custom` → custom, anything not in the roster (including `main`/`subagent`) → `external`. `roleKind = roles?.find(r => r.name === role)?.source ?? "external"`, and drop the `NEUTRAL_ROLES` branch. `KINDS = ["preset","custom","external"]`, labelled `Preset / Custom / External`. Kind facet tooltip: "External: Claude Code built-in, plugin or ~/.claude/agents agent, not managed by claude-manager". `KIND_ICON.external = Bot`.
- **Check:** with the seed, Roles → By role → Kind shows `preset` for the 6 presets and `external` for the other 9. No row says `custom`. The Kind facet counts are 6 / 0 / 9.

### P0-2 · Non-preset role hues collide with presets; dashed border invisible (user finding 4)
- **Where:** `src/web/lib/color.tokens.ts:81-94` (`fnv1a32 % 6 + 1`), `src/web/components/role.badge.tsx:6-13`, `src/web/components/tone.badge.tsx:13-26`
- **Problem:** hashing into the same 6 slots gives `general-purpose` the coder green and `Explore`/`Plan`/`web-fetch` the manager purple. At 1px, `border-dashed` cannot be seen (crop `roles-top.png`).
- **Why:** colour means identity. Two different agents in the same hue is a false signal, which breaks the dataviz rule "colour follows the entity". The 4 family hues plus 6 role hues already use every distinguishable hue we have, so a hashed 7th+ hue will always collide with something.
- **Fix (recommended):** colour is reserved for the 6 presets (solid tint, unchanged). Every other role renders **neutral**, with the icon carrying the kind:
  - custom: `TONE_CLASSES.neutral.badge` (solid neutral tint), icon `UserRound`;
  - external: `border-tone-neutral-border bg-transparent text-muted-foreground`, icon `Bot`. `main` keeps `SquareTerminal`.
  - `roleColor()` returns `{ slot: null, kind }` for non-presets. Delete `dashed`, `fnv1a32` and `RoleColor.custom` (dead after this change).
- **Check:** in light and dark, no non-preset badge shares a hue with manager/architect/coder/reviewer/researcher/writer. `general-purpose` is grey with a Bot icon, and a custom role is grey with a UserRound icon. `bun test test/web.color.test.ts` is updated and passes.

### P0-4 · KPI deltas like "↑ 60207.3%" are meaningless
- **Where:** `src/web/pages/overview.page.tsx:30-38,93-95`, `src/web/lib/format.ts:73-77`, `src/web/components/kpi.card.tsx:7-43`
- **Problem:** the previous period is close to zero, so the percentage explodes. Cost/Requests/Sessions show 60207%, 12589% and 1537%.
- **Why:** Stripe and Vercel switch to absolute comparison when the base is tiny. A percentage of nearly nothing is noise.
- **Fix:** rule in `overviewDeltas`: when `prev < DELTA_MIN_BASELINE[kpi]` (`{cost: 1, requests: 50, sessions: 5}`) **or** `|Δ| > DELTA_MAX_PCT` (500), return `{ value: null, prevLabel }`. `KpiDelta` gains `prevLabel?: string`, and `DeltaLine` then renders `from $8.23 prev 30d` (arrow by sign, neutral ink). `prev === 0` → "New this period". Show percentages with 0 decimals when ≥ 10% (`↑ 24%`) and 1 decimal below that.
- **Check:** with the seed, the Est. cost KPI reads "↑ from $8.23 prev 30d" (the value prev holds), and no KPI shows more than 3 digits before the "%".

### P0-5 · By model / By role are unreadable at 1024
- **Where:** `src/web/pages/roles.page.tsx:135`
- **Problem:** `lg:grid-cols-2` puts two tables in about 470px each at 1024. Model names truncate to "opus…", role badges to "man…", and the tier badge in group headers disappears (only the count "5" remains).
- **Why:** a table must never truncate its key column to the point where it can't be identified.
- **Fix:** `grid gap-6 xl:grid-cols-2 [&>*]:min-w-0` (stacked below 1280).
- **Check:** at 1024, every model and role name in both tables is fully visible, and the group header shows the `think` badge.

### P0-6 · Roles page renders an empty table while loading
- **Where:** `src/web/pages/roles.page.tsx:58,88-97,127`
- **Problem:** before data arrives, `specs = groupBy([])` is `[]` (not `undefined`), so `TableBody` maps zero groups. You see a header with nothing under it and no skeleton (screenshot `roles-error-dark-1440.png`). The summary reads "0 roles · 0 models".
- **Why:** an empty table during loading reads as "no data".
- **Fix:** `groups={data ? specs : undefined}` and `rows={data ? (group === NO_GROUP ? t.page : t.filtered) : undefined}`. Description: `data ? "… · N roles · M models" : RANGE_LABEL[range]`. This touches first load only, not the refresh path.
- **Check:** throttle `/api/roles` in DevTools: 8 skeleton rows appear, and "0 roles" never shows.

### P0-7 · At 390, Roles and Live sit off-screen in a horizontally scrolling nav
- **Where:** `src/web/app.tsx:83-126`, `src/web/components/theme.toggle.tsx:45-62`, `src/web/components/range.picker.tsx:16`
- **Problem:** row 2 is a scroll strip plus a range select, so 2 of the 5 destinations are hidden behind a fade. Row 1 spends about 120px on a 3-button theme switch.
- **Why:** the standard for 5 or fewer destinations on mobile is that all of them are visible (iOS tab bar, Linear mobile). A scrolling primary nav is not acceptable.
- **Fix:** below `sm`, row 2 = `<nav className="grid grid-cols-5">`. Each link is `flex min-h-12 flex-col items-center justify-center gap-0.5 text-[11px]`, icon `size-4` (always shown), active state `text-foreground` plus a 2px `bg-foreground` top bar. Remove `useMoreRight` and the mask. Move the native range `<select>` into row 1 (before the theme). The theme toggle renders a single cycle button (`size-11`, system → light → dark) below `sm` and keeps the 3-button group from `sm` up.
- **Check:** at 390, all 5 nav labels are visible, `nav.scrollWidth === nav.clientWidth`, the header is at most 108px tall, and the range is reachable in row 1.
